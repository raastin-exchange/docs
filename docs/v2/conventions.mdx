# قراردادها و قواعد عمومی

این صفحه قواعد عمومی نسخه v2 را جمع‌بندی می‌کند تا قبل از مراجعه به اندپوینت‌ها یک‌جا قابل مرور باشد.

## فرمت نماد

نماد در v2 به‌صورت فشرده و بدون جداکننده ارسال و دریافت می‌شود:

| ورودی پذیرفته‌شده | شکل کنونیکال در پاسخ |
| --- | --- |
| `BTCUSDT` | `BTCUSDT` |
| `BTC-USDT` | `BTCUSDT` |
| `BTC/IRT` | `BTCIRT` |

برای فهرست کامل نمادها همراه با `tickSize`، `stepSize`، حداقل/حداکثر مقدار و ضریب اهرم، از اندپوینت [`GET /api/v2/exchangeInfo`](../orders/exchange-info) استفاده کنید.

## احراز هویت

تمام مسیرهای v2 (به‌جز `/time` و `/exchangeInfo`) با توکن JWT احراز هویت می‌شوند:

<div dir='ltr'>

```
Authorization: Bearer <JWT>
```

</div>

برای دریافت توکن، به پنل کاربری خود مراجعه کنید.

## ساختار JSON

- کلیدها به‌صورت **camelCase** (مانند `clientOrderId`، `quoteOrderQty`).
- مقادیر شمارشی (enum) به‌صورت **UPPERCASE** (`BUY`، `SELL`، `LIMIT`، `MARKET`، `GTC`، `NEW`، `FILLED` و ...).
- اعداد اعشاری همیشه به‌صورت **رشته** (`"45000.00"`، `"0.001"`). هرگز عدد JSON خام نفرستید — برای حفظ دقت decimal، رشته الزامی است.
- تایم‌استمپ‌ها به‌صورت **میلی‌ثانیه یونیکس** (عدد صحیح).

## پاسخ خطا

پوشش خطا در همه‌ی اندپوینت‌ها یک‌سان است:

```json
{
  "code": -2010,
  "message": "Insufficient balance.",
  "field": "quantity"
}
```

| فیلد | معنا |
| --- | --- |
| `code` | کد عددی پایدار. ربات‌ها باید بر اساس این کد منطق خود را بنویسند، نه روی پیام انسانی. |
| `message` | توضیح کوتاه. |
| `field` | فقط برای خطاهای validation که به یک فیلد خاص از درخواست اشاره می‌کنند. |

### جدول کدهای خطا

| کد | HTTP | معنا |
| --- | --- | --- |
| -1000 | 500 | خطای ناشناخته |
| -1013 | 400 | مقدار نامعتبر (نقض stepSize / minQty / maxQty) |
| -1100 | 400 | پارامتر دارای فرمت نامعتبر |
| -1102 | 400 | پارامتر اجباری ارسال نشده |
| -1121 | 400 | نماد ناشناخته |
| -1130 | 400 | مقدار نامعتبر برای پارامتر |
| -2010 | 400 | موجودی کافی نیست |
| -2011 | 400 | لغو رد شد (سفارش یافت نشد یا در وضعیت مناسب نیست) |
| -2013 | 404 | سفارش وجود ندارد |
| -2014 | 401 | توکن نامعتبر است |
| -2026 | 400 | درخواست اصلاح رد شد |
| -3000 | 400 | پارامتر مارجین نامعتبر (positionSide، leverage و ...) |
| -3010 | 400 | پوزیشن یافت نشد یا بسته شده است |
| -4000 | 429 | محدودیت تعداد درخواست‌ها (rate-limit) |
| -5000 | 503 | سرویس معامله در دسترس نیست |

## صفحه‌بندی (cursor)

تمام اندپوینت‌های لیست از یک قرارداد یکسان برای صفحه‌بندی استفاده می‌کنند:

### پارامترهای کوئری

| نام | نوع | توضیح |
| --- | --- | --- |
| `fromId` | int64 | از کرسر قبلی (مقدار `nextCursor`). بدون آن، صفحه‌ی اول برمی‌گردد. |
| `limit` | int | تعداد ردیف. پیش‌فرض 100، حداکثر 1000. |

### قالب پاسخ

```json
{
  "data": [
    {/* ... یک ردیف ... */}
  ],
  "nextCursor": "20480",
  "hasMore": true
}
```

- `nextCursor` همان `id` آخرین آیتم در `data` است. در درخواست بعدی به‌عنوان `?fromId=20480` ارسال کنید.
- اگر `hasMore` برابر `false` باشد، پایان نتایج رسیده‌اید و `nextCursor` خالی می‌ماند.
